# 11 对 CIFAR-100 模型的七组配方比较与训练

本轮根据 2026-11-18 的训练授权执行：不同教师—学生配对可以选用不同配方，同一配对的七种方法共用一套配方。历史权重继续保留；新结果单独归档，不与历史结果拼接为同配方比较。

## 配方选择

每对比较四个组合：学习率 `0.01 / 0.05` × CE/KD 权重 `0.1/0.9 / 0.5/0.5`。范围包含已有的 early_double、compact_double 配方及交叉组合。选择依据是普通线性头 KD 的验证结果，不为不同方法单独调学习率和损失权重。

- 从 CIFAR-100 的训练集每类固定划出 50 张，共 5,000 张作为学生验证集；其余 45,000 张用于配方搜索。先划分原始图像，再生成弱/强两种增强，避免同一图像的两个视图跨越划分。
- 每个候选先训练 60 轮，使用完整 240 轮计划的前 60 轮，而非压缩学习率计划。按最后 5 轮平均验证 top-1 排名前二，随后从原 checkpoint 续训至 240 轮。
- 两个完整候选按第 236–240 轮平均验证 top-1 选择；相同则优先较低 CE，再按固定候选名称打破平局。完整保存筛选与最终选择依据。
- 选定后的七组正式训练均从头开始，使用完整 50,000 张训练图像，以及同一个 seed `3301`。配方搜索 seed 为 `3300`，划分 seed 为 `20261118`。
- 官方 10,000 张测试图像不参与配方选择。正式结果统一使用第 240 轮 checkpoint；不选择测试准确率最高的中途快照。

这是有界搜索中实测较好的配方，不承诺全局最优。60 轮淘汰可能错过后期更好的候选；每对只有两个候选完成全长验证。教师使用已有的全训练集预训练权重，因此这 5,000 张仅对学生训练是留出的，不是教师从未见过的数据。

## 七种方法与共同设置

| 任务名 | 分类头 | 蒸馏 |
|---|---|---|
| `kd` | 线性头 | 普通温度 KL |
| `cosine_kd` | 余弦头，通用初始化 | 普通温度 KL |
| `cosine_etf_kd` | ETF 初始化的余弦头，方向随后自由学习 | 普通温度 KL |
| `rotating_etf_kd` | 保持 ETF 几何、学习旋转方向 | 普通温度 KL |
| `cosine_sicd` | 余弦头，通用初始化 | SICD |
| `cosine_etf_sicd` | ETF 初始化的余弦头，方向随后自由学习 | SICD |
| `rotating_etf_sicd` | 保持 ETF 几何、学习旋转方向 | SICD |

共同设置：240 轮、batch 64、SGD momentum 0.9、weight decay 0.0005、学习率在 150/180/210 轮衰减为原来的 0.1、温度 4、余弦尺度 30、每张图像弱/强双视图、FP32、关闭 TF32。每对还固定教师文件及 SHA256、数据顺序、增强、特征维度和初始化 seed。

ResNet20、ResNet32、WRN40-1 原特征为 64 维。为支持 100 类严格 ETF，这三种学生在**所有七组及配方搜索中**统一加入 `Linear(64,128) → ReLU` 特征层；这些是升维后的对照，不能冒充原始 64 维架构的结果。SICD 的骨干梯度范数包含这个共同特征层，排除最后分类器。

可训练 ETF 使用最小 `C−1` 列正交 frame，对梯度进行切空间投影，SGD 后以正对角 QR 回缩，并同步投影 momentum。frame 的范数在约束流形上恒定，其权重衰减设为零；其余参数使用共同 weight decay。该实现与旧 D×C frame 的历史实现分别记录。ETF 初始化与旋转 ETF 的初始类方向保持一致。

## 任务数量和顺序

11 对 × 4 个候选 = 44 个筛选训练，其中 22 个晋级者从 60 轮续训到 240 轮；随后 11 对 × 7 组 = 77 个正式训练。总计 121 个独立训练轨迹、143 个调度阶段，第一轮正式实验每组只跑一个 seed。

两张 A100 80GB（GPU 0、1）各运行一个任务。初始优先 ResNet32×4→ResNet8×4，随后按配置中的配对顺序执行。某配对完成筛选后，优先执行其晋级验证和正式七组，正式组先补三种 SICD 设置。失败任务保留日志并停止该任务，不自动更换配方或无限重试。

## 运行和检查

协议：[configs/studies/cifar100_seven_arms_20261118.json](../configs/studies/cifar100_seven_arms_20261118.json)。调度器：[tools/run_pair_sweep.py](../tools/run_pair_sweep.py)。启动工具：[tools/launch_pair_sweep.py](../tools/launch_pair_sweep.py)。

运行目录为 `outputs/seven_arms_20261118/`：

- `manifest.json`、`source/`、`teachers/`：固定的源代码与教师副本、文件 SHA256、原数据摘要。
- `protocol.json`、`split.json`：本次协议与完整训练/验证划分。
- `preflight.json`：77 种组合的真实数据 GPU 前向、反向、优化器更新与 ETF 几何检查。
- `state.json`、`worker-0.json`、`worker-1.json`：动态队列、GPU 工作进程与心跳。
- `tuning/<pair>/<candidate>/`：筛选/晋级的 checkpoint、历史、进度及控制台日志。
- `selected/<pair>.json`：该配对的选择依据与七组共用配置摘要。
- `final/<pair>/<arm>/`：正式结果及可恢复的 `latest.pth`、`history.jsonl`、`final.json`、`progress.json`。

从 ACD 根目录查看状态：

```bash
../KD/.venv/bin/python -B -m tools.run_pair_sweep status
```

训练由独立 tmux socket `acd-seven-arms-20261118` 的 `gpu0`、`gpu1` 会话托管。worker 每次领取任务前检查 GPU 是否被其他进程占用以及剩余磁盘空间，不终止其他训练。中断后从最近完整 epoch 恢复；部分 epoch 不作为完成结果。需要暂停排队时可在运行目录创建 `PAUSE` 文件，当前训练完成后暂停领取新任务。

本轮没有执行模型上传或 git push。CPU 检查覆盖几何约束、配对初始化、升维参数归属、数据划分、分阶段续训、配方选择和产物校验；检查结果和实际启动状态另存于运行目录。
