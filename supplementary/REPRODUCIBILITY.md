# Supplementary reproducibility record

This page gives the commands and evidence paths behind the supplement.  It is
written for an evaluator who has cloned `laniusnan/ACD` at or after commit
`d4030fa`.

## Environment

Use Python 3.11 or newer with a PyTorch and torchvision pair compatible with
the target hardware:

```bash
pip install -e .
python -m unittest discover -s tests -v
```

The released evaluations use FP32 and disable TF32.  CIFAR-100 evaluation uses
the official torchvision test split with tensor normalization mean
`(0.5071, 0.4867, 0.4408)` and standard deviation `(0.2675, 0.2565, 0.2761)`.

## Reproducing Table S1 from published weights

Download the seven-arm release and run a full official test-set verification:

```bash
gh release download cifar100-seven-arms-res32x4-res8x4-20261118 \
  --repo laniusnan/ACD --dir checkpoints/seven-arms
python -m tools.verify_release \
  --release-dir checkpoints/seven-arms --data-root data/cifar100 \
  --device cpu --threads 2
```

`verification.json` is written into the release directory.  It checks every
asset against the release manifest SHA-256 value, evaluates all eight weights
(seven students and one teacher), checks the 10,000-image sample count, and
compares each student endpoint with its archived Top-1 to tolerance.

The training protocol and pre-registration record are:

- `configs/studies/cifar100_seven_arms_20261118.json`
- `docs/seven_arm_training_20261118.md`
- `docs/releases/cifar100-seven-arms-res32x4-res8x4-20261118.md`

## Reproducing Table S2 from published weights

The frozen rerun release has a separate manifest and downloader:

```bash
python -m tools.download_models --pair res56_res20 --student-only
python train.py --config configs/res56_res20.json --data-root data/cifar100 \
  --download --evaluate checkpoints/acd_res56_res20_s3201_e240.pth \
  --device cpu --workers 0
```

The authoritative endpoint record is `results/cifar100_rerun.json`.  The
published-weight and full-test verification records are in
`docs/release_publication.json` and `docs/release_verification.json`.

## Reproducing the oracle diagnostic

The figure uses a historical frozen endpoint and is not regenerated by the
main training CLI.  Its source code, data identity, optimizer details, values,
and rendered-file hashes are retained under:

- `research_archive/figures/analysis_20261116/probe_cifar100_same_state.py`
- `research_archive/figures/analysis_20261116/fig_oracle_calib_seed2051.json`
- `research_archive/figures/analysis_20261116/fig_output_mismatch_cifar100_seed2051.pdf`

The record fixes seed 2051, epoch 240, the CIFAR-100 test ordering, all 10,000
samples, $T=4$, objective factor 8, and the constraint $\alpha\ge0$.

## Scope of a successful reproduction

Reproducing a released endpoint means matching its evaluation metrics and
asset identity.  It does not assert bitwise recreation of the historical
training trajectory: the seed-3201 rerun is a frozen reconstruction and the
portable release files intentionally omit optimizer and scheduler state.
